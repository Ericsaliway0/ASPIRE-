# TCGA Driver Gene Labeling Pipeline

Builds a driver vs. non-driver gene label set for machine learning by combining:

- Somatic mutation frequency across 24 TCGA cancer types (via the GDC API)
- Known cancer driver genes from the COSMIC Cancer Gene Census
- Reactome pathway membership, restricted to disease-related pathways

## Pipeline overview

1. **Mutation frequency** (`scripts/run_mutation_frequency_pipeline.py`)
   Downloads masked somatic mutation (MAF) files for each cancer type from
   the GDC API and computes, per gene, the fraction of samples in which it
   is mutated.

2. **Gene labeling** (`scripts/run_driver_labeling_pipeline.py`)
   - Builds a protein-coding gene universe from a GENCODE GTF annotation.
   - Labels COSMIC Cancer Gene Census genes as drivers (`label = 1`).
   - Excludes any gene with driver evidence in NCG, CGC, IntOGen, **or**
     Bailey et al. 2018 from the non-driver candidate pool (not just CGC).
   - Filters the remaining candidates:
     - genes with mutation frequency >= 1% in any TCGA cancer type, and
     - genes belonging to a Reactome pathway that is a descendant of the
       top-level "Disease" pathway (`R-HSA-1643685`) in the pathway
       hierarchy.
   - Samples the final negatives via **length- and expression- (and
     optionally mutation-rate-) matched sampling** against the driver
     genes, rather than treating every surviving candidate as an equally
     valid negative (see "Negative sampling" below).
   - Saves the final labeled gene set (`label = 0` for non-driver).

## Required input data

Place the following files under `data/` (not included in this repository
— see `.gitignore`):

| File | Description |
|---|---|
| `data/gencode.v49.basic.annotation.gtf` | GENCODE gene annotation |
| `data/Census_allWed.tsv` | COSMIC Cancer Gene Census export |
| `data/reactome/ReactomePathways.gmt` | Reactome pathway gene sets |
| `data/reactome/reactome_relations.csv` | Reactome pathway parent/child relations (columns: `reactome_id_1`, `reactome_id_2`) |
| `data/NCG_cancergenes.tsv` | Network of Cancer Genes driver list (column: `symbol`) |
| `data/IntOGen_drivers.tsv` | IntOGen driver gene compendium (column: `SYMBOL`) |
| `data/Bailey2018_drivers.tsv` | Bailey et al. 2018 pan-cancer driver genes (column: `Gene`) |
| `data/gene_median_expression.csv` | Median expression per gene (columns: `gene`, `median_expression`) |

NCG/IntOGen/Bailey and the expression file are optional — if a file is
missing, that source is skipped (with a printed note) rather than causing
the pipeline to fail; column names for each source are configurable via
the `gene_col=` argument on the corresponding loader in
`src/negative_sampling.py` if your export uses different headers.

`data/mutation_frequency_tcga.csv` is generated by the first pipeline step
and consumed by the second.

## Usage

### Notebooks (recommended for interactive/exploratory runs)

```
notebooks/01_mutation_frequency_pipeline.ipynb   # download MAFs + compute mutation frequency
notebooks/02_driver_labeling_pipeline.ipynb      # build the driver/non-driver label set
```

Both notebooks import directly from `src/` and `config.py` at the repo root, so they always run
the same tested logic as the scripts below — there's no separate copy of the pipeline logic to
keep in sync. The first cell of each notebook `chdir`s to the repo root, so relative paths in
`config.py` (e.g. `data/...`) resolve correctly no matter where Jupyter's working directory
starts out. Run notebook 01 before notebook 02, since 02 consumes
`data/mutation_frequency_tcga.csv`.

### Scripts (recommended for unattended/CI runs)

```bash
# 1. Download MAFs and compute mutation frequency (requires network access)
python scripts/run_mutation_frequency_pipeline.py

# 2. Build the driver / non-driver gene labels
python scripts/run_driver_labeling_pipeline.py
```

Outputs are written to `data/processed/`:
- `gene_labels_driver_vs_nondriver.csv` — final labeled gene table
- `driver_genes.txt`, `non_driver_genes.txt` — plain-text gene lists

## Negative (non-driver) sampling

Negatives are constructed as: **random genes not in NCG/CGC/IntOGen/Bailey,
length- and expression-matched to the positives** (optionally also matched
on mutation rate — controlled by `MATCH_ON_MUTATION_RATE` in `config.py`).

Why matching, not just exclusion: driver genes tend to be longer and more
highly expressed than a random background gene (more exons/coding sequence
gives more opportunity for both real driver and passenger mutations to be
detected; higher expression means better sequencing coverage and more
reliable variant calling). Comparing drivers to an *unmatched* random
negative set lets a classifier learn "is this gene long/highly expressed"
as a shortcut for "is this a driver" rather than genuine driver biology.
Matching removes that confound.

Implementation (`src/negative_sampling.py`):
1. `build_driver_exclusion_set()` unions driver genes from NCG, CGC,
   IntOGen, and Bailey et al. 2018 — any gene in this union is ineligible
   to be a negative.
2. `match_negatives()` places every driver (positive) and every remaining
   candidate gene in log-transformed, z-scored covariate space (length,
   expression, optionally mutation rate) and, for each positive, finds its
   nearest not-yet-used candidate(s) via a KD-tree — i.e. nearest-neighbor
   matching without replacement. `NEGATIVES_PER_POSITIVE` in `config.py`
   controls how many matched negatives to draw per positive.
3. `summarize_matching_quality()` reports median covariate values for
   positives vs. matched negatives vs. the full unmatched candidate pool —
   include this table in the manuscript as evidence the matching worked
   (matched negatives should sit close to positives; the unmatched pool
   should not).

Running `scripts/run_driver_labeling_pipeline.py` with
`USE_MATCHED_NEGATIVE_SAMPLING = True` (default) writes two extra
diagnostic files to `data/processed/`:
- `negative_gene_matches.csv` — one row per (positive, matched negative,
  match distance)
- `negative_matching_quality.csv` — the covariate summary table above

## Notes on filter design

- **Gene universe** is restricted to `gene_type == "protein_coding"` entries
  in the GTF. An earlier version kept every gene biotype (lncRNAs,
  pseudogenes, miRNAs, etc.), inflating the universe from ~20,000 to
  ~77,000 genes.
- **Mutation-frequency filter** treats a gene absent from the mutation
  frequency table as having frequency 0 (i.e. never observed mutated),
  rather than excluding it by omission. It also compares against the
  maximum frequency across all cancer types per gene, consistent with
  "exclude if frequently mutated in *any* cancer type."
- **Pathway filter** is restricted to Reactome pathways that are hierarchy
  descendants of the top-level "Disease" pathway, rather than every pathway
  in the full Reactome catalog (which spans unrelated biology such as
  metabolism, translation, and vesicle transport).
